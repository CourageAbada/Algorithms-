# Phase 0.5 Final Report

Status: complete, awaiting review. Phase 1 not started. No broker contact, no orders. Full evidence: `PHASE0_5_UPSTREAM_DEEP_DIVE.md`.

1. **What changed from Phase 0.** Upstream conclusions are now based on source, not READMEs. Vibe-Trading's Forex engine was inspected and rejected as a base; three of its utilities became ADAPT candidates (purged CV, multiple-testing statistics, hash-chained audit ledger). FreqAI's train/test split was found to lack purging. MT5 facts were verified against the unpacked official package; time semantics stayed unverified. Architecture simplified to a single-machine engine (no collector/ZeroMQ, D-4). Decisions D-1..D-11 applied: `core/safety.py` (HALT_NEW_TRADES / EMERGENCY_FLATTEN), `HistoricalDataProvider`, Java moved to `legacy/java/`, licensing record, CI with secret scan, invented validation thresholds removed (D-6), instrument-specific XAUUSD-first statement.
2. **Vibe-Trading code actually inspected** (commit `7f6908b`): `backtest/engines/{forex,base,_market_hooks,composite}.py`, `backtest/{metrics,validation,runner,run_card,models}.py`, `backtest/loaders/mt5_loader.py`, `trading/connectors/mt5/{_client,orders,reads,profiles}.py`, `live/{halt,sdk_order_gate}.py`, `live/runtime/flatten.py`, `quantlib/{crossvalidation,multipletesting,microstructure,impact,risk}.py`, `governance/ledger.py`, plus agent/grounding/swarm/hypotheses/shadow_account structure. Upstream tests run: 86 passed (CV + multiple testing); 183 passed/1 env failure (forex/MT5); 58 passed/1 env failure (governance/halt/hypotheses).
3. **Reuse its Forex engine?** No. It is a bar-based target-weight engine with next-bar-open fills, a static spread/swap/pip table, zero commission, and **no stop-loss/take-profit/intrabar logic** at all. Patterns only (immutable fill records, rejection reasons, warm-up separation).
4. **Reuse its MT5 functionality?** Reference only. Loader = bars only (no ticks anywhere), no time-offset calibration. Connector has good ideas (demo/real/contest guard, size guards floored to lot step, order_check first, lock, hedging caveat) but re-initialises and shuts down the terminal on every call and sends no SL/TP.
5. **Reuse its metrics?** Only small pieces (trade statistics, drawdown against initial-cash high-water mark, `None` profit factor when no losses), adapted with our tests. It lacks expectancy, R, MFE/MAE, cost breakdown and segmentation, and its Sharpe is per-bar. Its "walk-forward" is an equity-curve window split, its bootstrap is i.i.d., and its Monte Carlo test checks path order not edge: not used as validation.
6. **Useful Qlib concepts.** Infer/learn processor split with explicit train-only fit windows; rolling-task generation with leakage truncation; experiment records tied to config/data. No Qlib code needed (equity cost model, daily/1-min equity data, MLflow weight).
7. **Useful FreqAI concepts.** Sliding-window retrain with predict-until-expiry; model expiry guard; inference-time novelty/outlier gate that suppresses prediction; recency weighting; persisted per-identifier artefacts. Not copied (GPL-3.0 verified). Negative finding: no purge/embargo in its split; automatic deployment of the newest model is forbidden by our policy.
8. **MT5 assumptions now verified** (from wheel 5.0.6231 source/metadata/binary strings): Windows x86-64 only; MIT metadata; numpy dependency; function names and signatures (incl. `initialize` `timeout`/`portable` args, `order_calc_margin/profit`); all trade/order/deal/tick-flag/timeframe/account-mode/retcode constants including `ACCOUNT_TRADE_MODE_DEMO/CONTEST/REAL` and margin modes; result struct names; field-name presence for symbol/account/terminal/tick/order structs; bundled `Buy/Sell/Close` helpers have fixed deviation and blind retries (rejected).
9. **Still unverified** (turned into Phase 1 verification tests): whether returned timestamps are UTC or server time (docs say UTC, community reports ~3 h offsets), server DST rules, struct field types/units, tick history depth and `copy_ticks` row limits, `SYMBOL_FILLING_*` bit values, hedge-vs-close behaviour, thread-safety, call latency, DOM availability, whether `initialize` can launch the terminal.
